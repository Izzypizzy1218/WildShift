# WildShift v1.2.9 코드 리뷰

후속 상태: 아래 두 발견 사항은 v1.2.10에서 수정했다. 원래 재현 기록은 보존하며, 변경 내용과 검증 범위는 [수정 문서](Recovery-v1.2.10.md)에 정리했다.

검토일: 2026-09-09. 현재 작업 폴더의 C# 37개, 런타임 XML 11개, 번역 키, 관련 테스트와 문서를 검토했다. 설치된 RimWorld 1.6 코드의 컨테이너·월드 등록·삭제·소지품 드롭 동작과 대조했다. 이번 작업은 리뷰이며 제품 코드와 설치본은 수정하지 않았다.

## 발견 사항

### 1. [P2] 컨테이너 복귀 실패 후 월드 복귀로 진행하여 상단에서 인물이 이탈함

- 위치: `Source/WildShift/TransformUtility.cs:359-365`, `TryReplaceInHoldingOwner`, `TryReplaceWorldPawn`.
- 조건: 월드에 등록된 상단 구성원이 동물 형태이고, 상단 컨테이너가 인간을 받아들이는 작업이 거부되거나 실패하지만 월드 등록 자체는 정상인 경우.
- 원인: `TryReplaceInHoldingOwner`는 동물과 보관된 인간을 복구하고 false를 반환한다. 호출자는 이를 컨테이너가 없는 경우와 구별하지 않고 `TryReplaceWorldPawn`을 실행한다. 이 함수는 여전히 상단에 소속된 동물인지 검사하지 않아서, 인간을 일반 월드 폰으로 내보낸 뒤 원래 동물을 삭제한다.
- 영향: 복귀 성공을 반환하지만 인간도 동물도 상단 명단에 남지 않는다. 인간 데이터는 월드에 남으므로 완전 삭제는 아니지만, 플레이어가 해당 인물을 조작할 수 없게 된다.
- 재현: 실제 프로덕션 복귀 함수를 사용하는 기존 엔진 스텁에 상단 컨테이너의 인간 수용 거부만 주입했다. 결과는 `ReturnedHuman=true`, `HumanInCaravanOwner=false`, `AnimalInCaravanOwner=false`, `HumanInWorldRegistry=true`, `AnimalDestroyed=true`, `OwnerMemberCount=0`이었다. 이는 실게임에서 자연 발생을 관찰한 결과는 아니다.
- 수정 방향: 컨테이너가 없었던 경우와 컨테이너 교체가 실패한 경우를 구별한다. 후자는 복구 후 실패로 종료하여 같은 상단에서 재시도하게 하고, 일반 월드 복귀는 실제로 소유 컨테이너가 없는 동물에만 허용한다. 치명상 긴급 구조 정책은 별도 경로로 유지한다.
- 재현 스크립트: 작업 공간의 `.tmp/wildshift-review-probe.ps1`.

### 2. [P2] 각성 후 원래 동물 삭제 실패 시 재시도로 인간이 중복 생성됨

- 위치: `Source/WildShift/Patch_Taming.cs:125`, `Source/WildShift/FormTransferUtility.cs:172-192`, `Source/WildShift/OwnedAnimalAwakening.cs:47-49`.
- 조건: 인간 생성·배치와 소지품 드롭은 성공했지만, 다른 모드 등의 삭제/디스폰 콜백이 원래 동물의 삭제 완료 전에 예외를 발생시키는 경우.
- 원인: `DestroyEmptyForm`은 삭제 실패를 기록하고 반환하지만 결과를 호출자에게 전달하지 않는다. 각성 함수는 성공 메시지까지 진행한다. 원래 동물에는 잠재 변신자 표식이 남고, 수동 각성의 실행 중 잠금은 finally에서 해제되므로 다음 클릭이 새 인간을 다시 생성한다.
- 영향: 동일한 동물에서 여러 정착민을 생성할 수 있다. 기존 중복 클릭 테스트는 첫 시도에서 원래 동물이 정상 삭제되는 경우만 보장한다.
- 재현: 제품 코드는 그대로 컴파일하고, 테스트용 `Pawn.Destroy` 스텁에 원래 동물 삭제 직전 예외를 주입했다. 수동 각성을 두 번 호출한 결과 `HumanBodiesGenerated=2`, `HumanBodiesAliveOnMap=2`, `OriginalAnimalAliveOnMap=true`, `AwakeningCommandStillEnabled=true`였다. 이 주입이 없는 기존 173개 안정성 검사는 그대로 통과했다. 실제 설치된 모드에서 해당 콜백 오류가 발생했다는 주장은 아니다.
- 수정 방향: 삭제 결과와 각성 완료 상태를 명시적으로 관리한다. 이미 인간이 생성된 동물은 새 인간 생성 대상으로 다시 취급하지 않고, 기존 인간을 유지하면서 남은 정리 작업만 재시도하도록 한다. 중간 상태를 저장·불러올 때에도 중복 생성이 없어야 한다. 짐 드롭 실패 후 생성된 인간을 정리하는 반대쪽 실패 경로에도 같은 원칙을 적용한다.
- 재현 스크립트: 작업 공간의 `.tmp/wildshift-review-cleanup-probe.ps1`. 주입은 메모리에서 만든 테스트 소스에만 적용되며 제품 파일과 기존 테스트 파일은 변경하지 않았다.

## 정상 경로 및 기존 제한

치료 각성의 플레이어 피해 이력 검사, 의료 영입 거부와 구매 예외의 구분, 수동 각성의 소유권·맵 상태 재검사, 최초 각성 시 네 종류 소지품 컨테이너 드롭은 검토 및 기존 스텁 검사에서 추가 결함을 발견하지 못했다. 저장된 ID 집합과 부활 후 이력 보존은 코드 구조 및 스텁 검사로 확인했으며 실제 Scribe 저장/로드나 부활혈청 플레이를 이번 리뷰에서 수행하지 않았다.

적 변신 처리는 대기 집합이 비었을 때 전체 폰을 순회하지 않고, 시작 시나리오 복구와 초상화 갱신에도 기존 제한 조건이 있다. 이번 리뷰에서 새로운 매 틱 전체 동물 검색은 발견하지 못했다. 실제 TPS/FPS는 측정하지 않았다.

이전 리뷰에서 남긴 숨겨진 인간의 일반 holder 탐색 누락, `Kill`을 통하지 않는 외부 직접 삭제, CE와 특수 동물 능력 호환성, 의수·생식·일반 변신체 장비 보존은 계속 별도 검증/설계 범위다. 오늘의 소지품 보존은 최초 잠재 변신자 각성에 적용되며 일반 동물 형태에서 인간으로 복귀하는 모든 경우로 확대된 것은 아니다. 기존에 보류한 인간의 쓰러진 상태에서 수동 변신하는 동작도 그대로다.

국문 Keyed 파일에는 복귀·변신·공격 설명과 시나리오 소개 등 일부 영어 문장이 남아 있다. 번역 키 연결 오류와는 별개의 미번역 상태다.

배포본의 정상 플레이에서 두 실패 조건을 관찰한 것은 아니다. 해당 예외가 일어났을 때의 잘못된 후속 동작을 재현한 결과이므로, 일반 플레이 재현과 구분하여 수정·회귀 검사하는 것이 적절하다.
