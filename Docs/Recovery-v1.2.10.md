# v1.2.10 복귀·각성 실패 처리 수정

v1.2.9 리뷰의 두 실패 경로를 수정했다.

- 상단/컨테이너에 인간을 넣지 못하면 원래 동물과 보관된 인간을 복구하고 실패로 종료한다. 소유 컨테이너가 없는 동물만 일반 월드 폰 복귀를 사용한다. 치명상 처리의 별도 긴급 구조 경로는 유지한다.
- 인간 배치와 소지품 드롭이 성공하면 원래 동물을 삭제하기 전에 각성 완료 ID를 기록한다. 삭제가 실패해도 재시도는 기존 동물 정리만 하며 인간을 다시 생성하지 않는다. 버튼은 **각성 마무리**로 표시된다. 이후 동물에 실은 짐도 정리 전에 내려놓는다.
- 생성/배치/짐 드롭 실패로 취소된 인간을 삭제하지 못한 경우, 정리 대기 기록을 보존한다. 이 인간의 삭제가 확인되어야 새로운 생성 시도를 허용한다. 배치된 인간을 저장 시 복제하지 않도록 맵·월드·외부 컨테이너에 속한 인간은 참조로, 아직 어디에도 배치되지 않은 인간은 깊은 저장으로 기록한다. 해석되지 않는 참조는 삭제 성공으로 간주하지 않는다.
- 각성 완료 ID는 인간의 사망이나 원래 동물의 부활로 초기화하지 않는다. 기록은 GameComponent에 저장하며 기존 Hediff의 타입은 바꾸지 않는다. 기존 저장에는 새 기록이 없으므로 빈 상태로 시작한다. 이전 버전에서 이미 만들어진 중복 인간은 자동으로 삭제하지 않는다.
- 일반 길들이기·치료·수동 각성의 공통 함수에 실행 중 잠금을 적용했다. 구매 예외와 치료 피해 이력 정책, 야생/상점 공통 3%, 다른 게임 설정은 그대로다. 주기적인 폰 검색이나 자동 삭제 루프는 추가하지 않았다.

## 확인

실제 제품 메서드를 엔진 스텁과 함께 컴파일하는 안정성 검사는 201개, 로직 검사는 89개로 총 290개를 통과했다. 새 검사는 28개이며 상단 수용 거부/이동 중 예외/재시도, 삭제 전후 예외/무반응, 반복 클릭, 완료 기록 저장, 인간 사망과 원래 동물 부활, 실패한 생성 취소, 참조/깊은 저장 분기, 기존 저장 호환, 일반·치료 경로의 재진입을 포함한다.

각 리뷰 결함을 테스트 소스에 되살리면 대응 회귀 검사가 실패하는 것도 확인했다. 실제 RimWorld/Unity/Harmony 참조로 빌드하고 Harmony 대상 31개와 XML 연결을 검사했다. 직렬화 검사는 실제 ExposeData의 분기를 스텁으로 실행하므로, 실제 Scribe cross-reference 해결이나 플레이를 재현한 검사는 아니다.

실게임에서는 별도 테스트 저장으로 정상 상단 복귀, 구매/치료 각성, 저장·불러오기를 확인할 수 있다. 외부 모드의 삭제 콜백 오류가 지속되면 정리도 계속 실패할 수 있지만, 이때 새 인간을 계속 만들지는 않는다. CE 및 특수 동물 능력 호환성은 이번 수정으로 추가 보장되지 않는다.
