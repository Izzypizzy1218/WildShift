# v1.2.11 성능·호환성 최종 점검

검토일: 2026-09-09. 현재 C# 38개의 패치·틱 진입점과 기존 캐시/큐 구조를 확인하고, 설치된 RimWorld 1.6.4871 및 VEF DLL과 대조했다. 로컬 활성 목록은 본체·DLC를 포함해 71개 항목이다. VEF, HAR, Alpha Animals, Megafauna, Dinosauria, RimHUD, Yayo Animation, RimTalk 등이 활성화되어 있고 CE는 설치되어 있지만 활성 목록에는 없다. 모든 활성 모드의 전체 소스를 감사하거나 실제 실행 중인 Harmony 패치 순서를 수집한 것은 아니다.

## 수정 내용과 비용 확인

| 경로 | 변경 | 검사 결과 |
| --- | --- | --- |
| 매 맵 틱의 적 변신 처리 | native `Map.GetComponent`의 목록 검색 대신 맵 생성 시 등록한 ConditionalWeakTable 사용 | 최초 등록 후 빈 처리 100,000회에서 컴포넌트 목록 및 폰 목록 검색 0회 |
| VEF 고정 성별 | 첫 맵 틱에만 변신체 여부를 확인하고 성별 변경 대기 플래그 해제. 원래 CompTick은 계속 실행 | 첫 처리 이후 100,000회에서 변신 상태 조회 0회 |
| 플레이어가 가한 피해 | 동물이 아니면 게임 컴포넌트 검색 전에 종료 | 인간 피해 콜백 10,000회에서 피해 기록 컴포넌트 검색 0회 |
| 폰 선택 UI | 잠재 변신자 소유 동물에만 각성 버튼 iterator 추가 | 일반 폰 선택 10,000회에서 원래 enumerable 객체 유지 |

맵 캐시는 약한 키를 사용해 종료된 게임/제거된 맵을 정적으로 붙잡지 않는다. 새 컴포넌트 생성 시 등록을 교체하고, 등록이 없을 때에는 원래 컴포넌트 조회로 복구한다. 변신 상태 자체는 캐시하지 않아 Hediff·소속 변경의 무효화 문제를 추가하지 않았다.

기존 적 대기 큐는 비어 있을 때 폰 검색과 배열 할당이 없다. 초상화 목록 검색은 dirty 상태일 때, 게임오버 보호는 120틱 캐시 만료 때 실행된다. 시작 시나리오 복구는 초기 성공 후 중단된다. 피해·각성 이력 기록에는 폰 전체 검색이나 새 주기적 작업을 추가하지 않았다. 비어 있거나 비정상적인 시작 시나리오의 복구 재시도는 기존 제한대로 남는다.

이 수치는 제품 메서드와 계측 스텁으로 확인한 호출/검색 횟수다. 실제 게임 TPS·프레임률·할당량 프로파일을 측정한 결과나 개선율은 아니다. 폰 생성 순간의 비용 및 대규모 습격의 체감 지연을 제거했다는 뜻도 아니다.

## 호환성 보강

1. 적 복귀 실패 후 실행하는 외부 `Lord.Notify_PawnLost` 콜백 오류를 해당 폰 단위로 격리한다. 다른 폰의 대기 중 복귀를 계속 처리하고 보관된 인간을 유지한다. 대기 플래그도 해제한다.
2. `MapPostTick` Prefix의 최상위 오류를 잡아 native 맵 처리 전체가 중단되는 것을 막는다. 콜백 및 안전 시점 오류는 ErrorOnce로 중복 로그를 제한한다. 외부 모드의 원래 오류 자체를 고친다는 의미는 아니다.
3. VEF 선택적 연동은 CompTick과 `changeGenderOnce`의 bool 타입·쓰기 가능 여부를 확인한다. 모드가 없거나 구조가 달라졌거나 패치 설치가 실패하면 경고 후 선택적 연동만 건너뛴다.
4. VEF 원본 콜백을 계속 실행하고 해당 변신체의 한 번짜리 성별 변경만 소비하므로, 원본 콜백 전체를 매번 건너뛰던 범위를 줄였다. 일반 동물의 고정 성별 처리와 로드 뒤 첫 틱 처리는 유지된다.

실제 설치 VEF의 `VEF.AnimalBehaviours.CompFixedGender` 메서드와 필드를 reflection-only로 확인했다. 검사한 DLL SHA256은 `AC39E9FA19FCFAA4379F737B6F0ECC74EEA242A6CCE7EADF62FC1D0E66ABABD6`이다. 별도 프로세스에서 실제 Harmony DLL로 동일한 private bool 구조의 모델을 패치하여 ref 주입, 원본 콜백 실행, 변신체 성별 보존, 일반 동물 성별 변경을 확인했다. 이 모델의 10,000회 호출은 변신 상태를 1회만 조회했다. 실제 VEF/Unity 플레이 테스트와는 구분한다.

## 남는 연동 경계

- 다른 모드가 같은 변신체의 메인/상시 ThinkTree를 교체하거나 징집 UI·식민자 판정을 재정의하면 패치 순서에 따라 서로 덮을 수 있다. 이번 수정은 타 모드의 전역 우선순위를 강제하지 않는다.
- 치명상 후 동물 폰을 계속 참조하는 전투 코드, `Pawn.Kill`을 통하지 않는 직접 삭제·변태·특수 소환/삼키기 등의 교체는 별도 검증이 필요하다. CE는 현재 활성 상태가 아니므로 호환 확정을 내리지 않았다.
- 일반 holder 탐색에 숨겨진 인간이 포함되지 않는 문제와 일반 변신체의 장비·생식·의수 보존은 이전에 보류한 범위다. 최초 각성의 짐 보존이나 이번 틱 최적화가 이를 해결하는 것은 아니다.
- 실제 저장/로드의 Scribe 참조 해결, 여러 동물 모드의 특수 능력, 전체 71개 활성 항목을 조합한 실게임 안정성은 이번 정적/모델 검사만으로 보장할 수 없다.

## 최종 검사

- 로직 89개 + 안정성 218개 = 307개 통과. 이번 성능·호환성 검사는 17개 추가.
- 별도 실제 Harmony private-field 주입 검사 통과.
- 설치 VEF 메타데이터, native Harmony 대상 31개·주입 필드 10개, enemy 관련 정확한 시그니처 10개 확인.
- XML 11개와 native think-tree 참조, 중복 Def·번역 키 검사 통과.
- 설치된 게임/Unity/Harmony 참조로 전체 빌드 성공.
- 확률·치료/구매 정책·쿨다운·전투 애니메이션·설정 파일은 변경하지 않았다.

재현 명령은 `Tests/Run-StabilityTests.ps1`, `Tests/Run-LogicTests.ps1`, `Tests/Run-OptionalHarmonyTests.ps1`, `Tests/Verify-GameApi.ps1 -VefAssembly <VEF.dll>`이다. 마지막 두 스크립트는 Windows PowerShell에서 실행한다.
