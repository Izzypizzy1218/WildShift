# Native combat target-search probe (TEST ONLY)

Build separately with `Run-CombatPerformance.ps1 -BuildOnly`, stage its test-only fixture mod in a private engine, then run with `-SkipBuild -FixtureDir ...`. Output must be fresh and outside the repository. No production installation or normal profile is modified. The runner refuses a concurrent RimWorld and may terminate only its own timed-out process.

The synthetic fixture creates a 75×75 cleared soil arena with deterministic test-pawn generation (95×95 for 240/400 hostiles). Human/transformed actors are drafted and use native `Wait_Combat` with fire-at-will; no explicit target is assigned. Loadouts are `rifle`, `jump` (a real human jump pack and no weapon), or `unarmed`. The ordinary-animal comparison uses explicit native melee jobs, and must not be described as an equivalent native drafted animal. Hostile human targets normally run ordinary native waiting jobs. `-EnemyAssault` enables native assault AI; the defaults alone do not simulate an adversarial raid.

`-BlockedLOS` places a full opaque wall between actors and targets. Treat it as a targeting diagnostic only when the recorded positions, charges, jumps and damage confirm that no attack or movement changed the intended state. An ordinary animal can path around the wall's end gaps; the flag alone does not prove a search-only workload. Unblocked rifle cases require actual successful native projectile shots to pass. Actual target and actor populations, jobs, searches, shots and damage events are sampled, because native combat can kill or down targets. No invulnerability, damage suppression, target replacement or attack method substitution is used.

The constant tick observer reports native tick timing histograms, TPS, thread allocations and process allocation deltas. A few constant activity counters remain in all cases. `-Diagnostic` additionally instruments native targeting/verb/stat methods and WildShift shared-state methods; its inclusive timings include nested calls and instrumentation cost, so compare performance using separate runs without this flag. Keep warmup and measurement durations identical across compared conditions.

Preflight records the actual effective verb, automatic/manual-allowed verb choices and manual-cast flags. This can reveal manual-only apparel abilities accidentally selected by native drafted-animal auto attack. The probe records evidence and does not patch that gameplay behavior.

`-RichGenes` applies the official native Sanguophage xenotype to original player actors and Hussar to hostile humans through `Pawn_GeneTracker.SetXenotype`; actual total/active gene counts are recorded. `-EnemyAssault` replaces stationary hostile jobs with a real native `LordJob_AssaultColony`. Both synthetic human and transformed cases receive the same extra unarmed normal-human anchor, giving the native assault a human objective even when every measured actor is transformed. Attackers are normally unarmed; `-EnemyLoadout rifle` adds native assault rifles to exercise incoming projectile/armor/shared-capacity work. Real damage, downing and deaths remain enabled and may invalidate a longer run. Successful hostile shots, actor bullet hits and raw pre-armor damage inputs are recorded separately. The fixture disables enemy shapeshifter generation only in the disposable assault scenario to isolate the player-form factor, records the prior/private values and restores the in-memory setting on exit without writing normal mod settings.

Samples include native enemy job/duty counts, actor positions, actual jump-pack charges, native jump-start counters and anchor survival. Target population is sampled rather than assumed constant during an assault. Native forced slow-time is reported, never bypassed; distinguish a 60-TPS native speed limit from high milliseconds per native tick.

`-GearPreset FullNative` gives the original human real cataphract apparel, native archotech limb/eye implants and a bounded set of supported native drug/serum/supercharge states. A shield belt is used only with the unarmed player loadout, so it cannot silently block the rifle comparison. `stress-state.json` records the actual native apparel and health state. `-Diagnostic` also observes health `DirtyCache` and shared gear/stat refresh methods. Inclusive instrumented times overlap and are for attribution, not additive CPU totals.

`-GraphicsMode Native` retains native graphics while the process starts hidden; `Headless` remains the default. `-SelectActors` uses native selection. `frame-result.json` records native Root.Update CPU, separate OnGUI CPU, frame-start intervals, early gameplay/measured frames and slow Root updates. Frame intervals include engine rendering/pacing and are not pure CPU or GPU timings; headless intervals are not display FPS. The first setup frame includes arena generation and pawn spawning. Use per-actor `Transitions` to distinguish transform/draft cost from that setup overhead. Histogram values above 100 ms are capped with overflow counts; maxima remain exact.

`Run-LiveCombat.ps1` loads a copied existing save in a private, separately staged mod profile and preserves its existing actor's real genes, health and equipment. It relocates only that disposable actor and adds native hostile riflemen without clearing terrain or buildings. Its `-Drafted:$false` control is permitted to remain undrafted. See the runner's required source-profile inputs; it never saves back to the source save. Native modpack errors remain strict failures. `native-error-window.json` separately records errors present before live setup, additions during setup/warmup and additions during measurement using text-multiset subtraction. This is evidence about recorded log entries; a clean delta does not certify the complete modpack or count errors suppressed by native logging.

Diagnostic v4 adds selected Biology bind/mutation/tick, Anatomy version/signature/capacity and Runtime tick methods, plus the command-recipient health patch. It does not claim coverage of every shared-state type. `shared-refresh-generations.json` counts actual Stats.State generation changes, source-condition captures, condition-result changes and systems/anatomy version changes without recomputing those signatures. These counters require diagnostic mode and retain its measurement overhead. Compare uninstrumented runs for performance claims.

Diagnostic v6 installs before transformation, after input/version/mod validation. `transition-hot-methods.json` contains separate per-actor transform and draft scopes, with inclusive method times/allocations and generation counters reset between scopes and before battle measurement. Initialization/bind/source-mutation and native StatWorker cache methods are included. Native cached StatWorker fields are inspected directly before/after each phase, without accessing `StatDef.Worker`; newly initialized definition names are recorded. Diagnostic installation and snapshot serialization are excluded from phase timings. Instrumented transition times retain observer overhead and must not replace uninstrumented comparison timings.

Live runner `-AwaitManagedSampler` is an optional handshake for external EventPipe sampling, including `-Diagnostic:$false` runs. After native control is ready and before Setup, the fixture writes `profile/CombatResults/managed-sampler-request.json` with PID and UTC/stopwatch timestamps. It waits through ordinary updates, for at most 30 seconds, for `<Output>/managed-sampler-ready.txt`; the external sampler must attach before creating that file. `managed-sampler-release.json` marks resumption. The fixture does not start a collector, sleep, force ticks or create the ready file. Default runs do not wait for a sampler.

Live v8 prewarms the loaded colony for `-LivePrewarmTicks 120` by default (`0` skips it), after the native pause gate and before the sampler handshake or Setup. Native updates use TimeSpeed.Normal, with a 60-second timeout and the same private storyteller/random-mental/random-disease debug gates as the arena fixture. `live-prewarm.json` separately records cold tick timings, allocations, actual tick count and elapsed time. The fixture then pauses and resets both aggregate and first-tick timing capture, so post-load mod initialization cannot be labeled as transformation time. Non-live arena runs do not prewarm.

Live v9 also prewarms the newly spawned enemies for `-LiveEnemyPrewarmTicks 30` ordinary ticks (`0` skips it), unarmed on native Wait jobs. The existing original is undrafted on a temporary native Wait job during this phase. `live-enemy-prewarm.json` records actual native ticks and cold costs separately. The fixture then pauses, clears that temporary original job, and resets timing before the optional sampler request and transform/draft continuation. Rifles are equipped and the native assault Lord is created only after this phase. Initial source state and a new pre-transform source snapshot are both preserved. Live drafting sets only Drafted/FireAtWill and lets native think trees choose jobs; live Care does not redraft or modify auto-undrafter timing. `native-job-activity.json` records native job starts and optional Orders/close-melee think counters, with installed flags. Arena forced-job comparisons remain unchanged.

Live v10 private Prefs use devMode=true only to permit native autostart. The live GameComponent FinalizeInit then switches actual Prefs.DevMode=false before any prewarming or measurement and records both values in `live-development-mode.json`. Before the trial, existing exact native debug-log windows are closed through native Close(false), with before/after error snapshots retained in `live-trial-ui.json`; errors are never cleared or suppressed. Other windows are retained. After enemy rifles and the assault Lord are set up, native StopAll releases the temporary warm Wait jobs; `live-enemy-job-release.json` records the released counts and before/after jobs. Actual native enemy shots and jobs must establish that a recorded trial exercised combat.

Live v11 sets up enemy rifles and the native assault Lord while the original is still human. After releasing temporary enemy Wait jobs, `-LiveArmedPrewarmTicks 15` ordinary Normal ticks allow native target acquisition before the sampler and transform/draft continuation (`0` skips these acquisition ticks). `live-armed-prewarm.json` records actual tick costs, enemy jobs, current verb/weapon/target, violence availability, distance and LOS to the human; `live-pretransform-combat-state.json` records the final source and enemy state. The existing assault Lord is reused after transformation. Real human death/downing fails the fixture. Target acquisition and firing must be established from the recorded state and activity, not assumed from the requested phase.

Selection v12 uses the separate `Run-SelectionProbe.ps1` runner. It preserves live v11 preparation, pauses immediately after the transformed/drafted trial is set up, and alternates selected/deselected/selected for 2 seconds each in the same battle state. `selection-result.json` records per-phase Root CPU, OnGUI CPU and allocations, Layout/Repaint counts, frame intervals, cursor positions, raw pawn health/genes/gear/job snapshots and camera fields. Paused phases require zero native ticks and stable state/camera; they are UI isolation, not combat TPS tests. Hover is explicitly labeled as not intentionally tested. Core live Care/speed overrides are bypassed during the sequence. `-SelectionRunning` optionally adds three 0.5-second Normal-speed phases with native tick/shot/damage counters; real casualties and state drift are retained and recorded.

`-SelectionUiDiagnostics` optionally adds inclusive UI-path timing for inspect/gizmo/tooltip/meditation methods and lazy native/WildShift gizmo iterator MoveNext paths. It is off by default for external EventPipe runs; inclusive times overlap and include observer overhead. Root CPU and OnGUI callbacks use independent phase observers, capture the phase at entry, and omit Root callbacks spanning a phase change. The existing FrameProbe remains separate. Native startup errors remain strict failures in the ordinary result; `selection-result.json` separately checks newly added errors for this bounded sequence.

Selection v13 reapplies runInBackground=true, targetFrameRate=60 and vSyncCount=0 at selection start, records actual settings/focus/screen coordinates per phase, and adds a one-second selected paused preroll before measurement. Paused measured phases require at least 20 Root and Repaint observations; optional running phases require at least one of each. A zero-frame or background-throttled sample cannot pass merely because its raw state stayed frozen. The frame-start intervals remain observations, not guaranteed display refresh or CPU cost.

The optional real-hit variant uses `Run-SelectionProbe.ps1 -SelectionRunningOnly -SelectionNativeSerums` with the selected native animal form and rifle enemies. Real native MindNumbSerum and Metalblood are applied to the human before transformation and recorded in `selection-native-serums.json`; this does not replace health/damage code or grant invulnerability. Running-only mode uses a one-second native Normal combat/selected-UI preroll followed by three one-second selected/deselected/selected phases by default. Per-phase snapshots include actual health percentage, pain, injury severity, armor HP and native shot/hit activity. A running-only case with requested enemies requires observed enemy shots and actor bullet hits to pass. `-SelectionGenerationDiagnostics` separately enables lightweight Stats generation and HediffSet.DirtyCache counters; broad shared-method profiling remains off unless separately requested. Existing paused defaults are unchanged.

`Run-SelectionDetailsProbe.ps1` is a separate runner; existing selection scripts remain unchanged. It defaults to requesting the supported native Health inspect tab and verifies available tabs, the opened type and visibility. Optional `-SelectionSyntheticHealthHover` temporarily puts only the current Layout/Repaint GUI event inside the first actual RimHUD HealthTooltip.Get rectangle in TooltipsPlus.Draw, then restores it in a finalizer. Per-phase output records attempts, Mouse.IsOver, input blocking and actual getter calls, and requires the requested selected-case getter to execute. The label is SyntheticHealthTooltipGetterHover: physical cursor/clicks are unchanged, and this does not establish that the visible tooltip window was rendered after the event position was restored.

`Run-PostHitSelectionProbe.ps1` first runs actual native Normal combat for 2 seconds after transformation, then freezes that one wounded state for three 3-second selected/deselected/reselected phases. `selection-posthit-warmup.json` requires actor survival, enemy shots, actor bullet hits, and increased native injury severity or real worn-armor HP loss. Every measured phase must stay on the same frozen tick with identical raw actor/original/enemy health, genes, gear, jobs and camera. Health tab and the scoped RimHUD health-getter hover remain optional. No damage is fabricated or overridden; a killed/downed/unhit actor fails the case.

Post-hit runner optional `-SelectionCoarseUiBuckets` times only outer RimHUD layout, gizmo grid, native Health tab, pawn render, portrait cache/bar and selection-overlay methods. `-SelectionModifierDiagnostics` separately times only Stats.State.Refresh/Build, Systems.ModifierVersion (the available longest overload), Anatomy.State.Refresh and Gear.State.Refresh, with allocation totals. Neither option instruments Hash, Gene.Active or every getter. Inclusive buckets overlap and contain observer overhead, so run a plain baseline separately. Broad profiler and sampler/running-comparison options are rejected by this dedicated runner.
