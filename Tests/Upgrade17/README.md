# Actual old-save probe (TEST ONLY)

This helper works with real native 1.6/net472 and 1.7/net10 engines. Build with explicit matching `RimWorldVersion`, `RimWorldDir`, `WildShiftPath`, `HarmonyPath`, external `OutputPath` and `BaseIntermediateOutputPath`. Stage the DLL and this directory's `About.xml` as `About/About.xml` in an isolated test-mod directory. The runner never builds, stages or installs mods itself, and the fixture must never be included in a runtime release.

`Run-UpgradeProbe.ps1` requires the actual engine, explicit old save, staged production/fixture directories, expected production SHA256 and a **new external** evidence directory. Its source save metadata supplies the original active mod IDs/order; every required original mod must be available in the selected game search path. No user mod settings or credentials are copied. The only extra active mod is this fixture. Cross-minor-version loads require explicit `AllowCrossVersion` and must be reported separately from same-version migration.

If a verified unavailable performance-only package must be omitted, pass its **original ID** explicitly through `ExcludedMods`. Exclusions must exist in the source metadata and cannot remove the game, DLC, Harmony or WildShift. The original requested list, exact exclusions and filtered ordered actual list are recorded; `SameModProfile=false` prevents claiming an identical mod-pack load. No substitute/fake package identities are introduced. An omitted content mod would still invalidate preservation coverage for its definitions, even if native loading completes.

The original save is copied byte-for-byte to external `source-copy.rws` and isolated `profile/Saves/autostart.rws`. The native `Root_Entry` autostart mechanism loads it. The probe pauses in `GameComponent.FinalizeInit` and records all relevant human/form/held-body state after native and production postload callbacks, without advancing game ticks. It captures exact IDs, species/assignment, owners, health/implant IDs/parts/severity/age, belongings, skill records, gene IDs and ability IDs/casters/cooldowns. It then uses native `GameDataSaveLoader.SaveGame`, closes its process, and a second fresh process compares the same snapshot.

An observational Harmony postfix also records native `PawnGenerator.GeneratePawn(PawnGenerationRequest)` results and call stacks to `phase-N-generation-trace.xml`. It changes no request/result, RNG, relation or transformation behavior. This separates a mod's load-time temporary human from WildShift's actual animal generation when diagnosing dangling references. Test-only tracing is absent from production DLLs and runtime packages.

Optional `CycleTargetId` permits a controlled production transformation cycle for **one explicit living player pawn on a map**. For an active old animal it returns the exact stored human, re-enters its source species and requires reuse of the original animal object. For an old human it enters the assigned form and returns the exact old human. Wounds reset on re-entry and animal belongings unload, so compare the pre-cycle and resave snapshots according to these intentional rules. Automatic destructive/death/respawn probes are not performed on real copied colonies.

**A first-load snapshot is not a serialized-source baseline.** A postload migration could already have removed an old state before the snapshot. Independently compare the immutable `source-copy.rws` XML with `phase-0-loaded.xml` (including missing health-sanitization flags, original/animal IDs, implants, possessions and progress) before claiming upgrade safety. The result explicitly leaves `SourceSerializedBaselineCompared=false`. This probe also does not serialize arbitrary custom comp fields into its XML; native full resaves retain them for a separate source/resave XML comparison.

`StatePassed`, `NativeErrorFree`, source-save preservation and normal-config preservation remain separate. Known mod-pack errors do not abort before loading; all raw logs and matching diagnostic lines are retained, and any error/exception keeps the overall `Passed` false. The runner may terminate only its own timed-out process and refuses other running RimWorld processes. Original saves and normal user configuration are never written by the runner.

For native 1.6, `GraphicsMode` defaults to `Batch` (`-batchmode` with a real D3D11 device). `-GraphicsMode GUI` omits only `-batchmode`, preserving native graphics/GUI initialization and the hidden owned window. This permits a real GUI-dependent mod such as RimHUD to initialize its actual font/style resources; no game, RimHUD or Unity API is replaced or mocked. The requested/effective mode and exact arguments are recorded for every process. Native 1.7 retains its existing `Headless` mode, regardless of this 1.6 option. A GUI-mode startup success would not itself establish rendered-graphics correctness or prove the batch crash's cause.
